# Interview Question Bank

This file accumulates concise interview questions and model answers as the project
progresses. Answers must describe only implemented and verified work.

## Module 0 — Repository foundation

### Why use a `src/` project layout?

It prevents accidental imports directly from the repository root and makes tests use
the installed package, which better matches production behavior.

### What problem does `uv` solve?

`uv` manages Python versions, virtual environments, dependency resolution, locked
dependencies, and command execution through one fast tool.

### Why commit `uv.lock`?

It records the resolved dependency versions so local development and CI can reproduce
the same environment.

### What is the difference between Ruff and Pyright?

Ruff checks style, formatting, imports, and common code problems. Pyright checks
whether Python values and function calls agree with declared types.

### Why use pre-commit?

It runs selected quality checks before a commit is created, catching simple problems
earlier. CI still reruns the checks because local hooks can be skipped.

## Module 1 — Domain and golden dataset

### What is a golden evaluation dataset?

It is a versioned collection of representative inputs with expected routes, sources,
facts, refusals, clarifications, or SQL results. It provides a consistent benchmark
for comparing system versions.

### Why create evaluation cases before optimizing retrieval?

Without frozen expected behavior, retrieval changes can only be judged informally.
An early dataset makes baseline-versus-candidate comparisons reproducible.

### Why include unsupported and malicious questions?

A production assistant must be evaluated not only on correct answers but also on
abstention, refusal, routing, and resistance to prompt injection.

### Why version the golden dataset?

Changing the test cases changes the meaning of the metrics. Versioning preserves
comparability and records exactly which cases produced a result.

## Module 2 — PostgreSQL and pgvector

### What is the difference between Psycopg, SQLAlchemy, and Alembic?

Psycopg is the PostgreSQL driver carrying requests between Python and the database.
SQLAlchemy defines and queries database structures using Python. Alembic versions and
applies database-schema changes.

### Why run PostgreSQL in Docker?

Docker provides a repeatable isolated PostgreSQL environment with a pinned version,
health check, persistent volume, and consistent startup process.

### What is pgvector?

pgvector is a PostgreSQL extension that stores embedding vectors and supports vector
distance operations and vector indexes.

### Why use PostgreSQL instead of a dedicated vector database?

For the portfolio-scale milestone, PostgreSQL combines relational records, analytics,
full-text search, metadata filtering, permissions, and vectors in one transactional
system. A specialized store will be reconsidered only if measurements justify it.

### What is a SQLAlchemy model?

It is a Python declaration describing a table, its columns, types, keys, constraints,
and indexes. It is a blueprint and does not create the real table by itself.

### What is an Alembic migration?

It is a versioned set of upgrade and downgrade instructions that transforms the real
database schema in a reproducible way.

### Why inspect autogenerated migrations?

Autogeneration can omit database-level objects or include unrelated changes. In this
project, review found a missing schema-creation statement, a missing vector import,
and unwanted constraint removals.

### What is the difference between a PostgreSQL database and schema?

A database is the main isolated data store. A schema is a named namespace inside that
database used to organize and permission related tables.

### What are primary and foreign keys?

A primary key uniquely identifies a row. A foreign key connects a row to another table
and prevents invalid relationships.

### What is the difference between a constraint and an index?

A constraint enforces valid data, such as positive expense amounts. An index is a data
structure that speeds retrieval. Unique constraints commonly create supporting
indexes.

### What does idempotent seeding mean?

Running the seed operation repeatedly produces the same final records without creating
duplicates. This project uses deterministic UUIDs and SQLAlchemy merge operations.

### Why use deterministic UUIDs?

The same logical record receives the same identifier on every run, enabling safe
upserts and reproducible evaluation data.

### Why use a read-only database role for Text-to-SQL?

Prompt instructions and application validation can fail. Database permissions provide
a final independent boundary that prevents generated SQL from modifying data.

### How are sensitive employee columns protected?

The analytics reader receives column-level access to approved employee fields but no
permission to read work email or salary. A future SQL allowlist will add another
validation layer.

### What is connection pooling?

It reuses established database connections instead of opening a new connection for
every operation. The current SQLAlchemy engine uses a bounded pool and checks stale
connections before reuse.

### How was the database foundation verified?

The project tested migrations in both directions, table and index creation, pgvector
installation, lexical and vector column types, deterministic seeding, approved reads,
restricted-column denial, write denial, constraints, and database connectivity.
